## 1. Absolute Clinical Disclosure: Zero Clinical Validation

### ⚠️ NOTHING IN THIS SYSTEM IS CLINICALLY VALIDATED
1. **No Medical Approval:** No component, model, heuristic, algorithm, or workflow within Aarogya-Drishti has been evaluated, approved, or certified by any regulatory or health authority, including:
   - Central Drugs Standard Control Organisation (CDSCO, India)
   - Indian Council of Medical Research (ICMR)
   - United States Food and Drug Administration (US FDA)
   - European Medicines Agency (EMA) / CE-IVD
2. **Demo AI Triaging Only:** The integrated machine learning triaging engine is a demonstration heuristic ("DEMO AI") provided solely to prove system dataflow, offline queueing, and UI rendering. It carries **zero diagnostic validity**.
3. **No Clinical Staging:** The system is explicitly blocked from determining lesion margins, histological grading, TNM staging, or curative intervention paths.
4. **Human Clinician Mandatory:** Under no circumstances should any clinical decision, referral denial, surgical intervention, or medical prescription be made on the basis of scores, tags, or outputs generated by this system. All patient care must be delivered directly by qualified, licensed medical professionals.

## 2. Cryptographic & Security Boundaries

### 2.1 Browser Cryptography vs. Hardware-Bound Keystore (Android)
- **Current Limitation:** In the web browser / PWA environment, offline IndexedDB data encryption relies on standard Web Crypto API implementations (AES-GCM-256) with encryption keys derived in memory or cached locally.
- **Hardware Security Gap:** A web browser sandbox **cannot match native Android hardware-bound key storage** (Android Keystore / ARM TrustZone / StrongBox Keymaster). An adversary possessing rooted physical access to the device or local browser debugging permissions could potentially extract stored session fragments from RAM.
- **Production Recommendation:** For production deployment in tribal field operations, the client PWA should be wrapped in an Android Trusted Web Activity (TWA) or native Android container integrating Android Keystore for hardware-isolated, non-exportable key storage.

## 3. Blocked External Adapters & Simulated Services

### 3.1 WebRTC Live Video & Voice Telephony (`BLOCKED`)
- **Status:** All video and audio streaming endpoints return status `BLOCKED`.
- **Rationale:** Live real-time audio/video streaming in remote tribal habitations requires specialized low-bandwidth WebRTC SFU servers and cellular infrastructure that does not exist in disconnected hamlets.
- **Current Capability:** Text-based secure case discussions and versioned clinical notes are fully operational. No fake call screen or mock video is displayed.

### 3.2 Native Cellular SMS Gateway (`BLOCKED`)
- **Status:** Real outbound cellular SMS transmission is `BLOCKED`.
- **Implementation:** Replaced with an in-memory simulated message dispatcher that validates message formatting and enforces non-diagnostic wording rules.

### 3.3 Live UIDAI Aadhaar Integration (`MOCK`)
- **Status:** Real UIDAI Aadhaar authentication is `BLOCKED`.
- **Implementation:** Operates as a completely isolated mock service (`mock: true`).
- **Data Protection:** Raw 12-digit Aadhaar numbers are never accepted, verified, stored, or logged. Only masked synthetic strings (`XXXX-XXXX-1234`) are permitted.

### 3.4 P4 AI Report Extraction (`DEFERRED`)
- **Status:** Automated AI extraction from unstructured clinical lab reports (P4) is explicitly marked `DEFERRED` per the project roadmap. Clinicians input biopsy parameters and attach PDF/image reports manually.

## 4. Architectural & Demographic Boundaries

### 4.1 Small-Count Suppression Boundaries
- While small-count cell suppression ($< 5$) is strictly enforced across all standard dashboards, map clusters, and CSV/PDF exports, highly specialized multi-attribute filtering across extreme micro-populations (e.g. searching an unpopulated hamlet of 6 people for an exact age) could yield sparse sets.
- Current mitigations return empty states rather than revealing isolated rows.

### 4.2 Verbatim Landmark Addressing
- Tribal hamlets lack formal postal street addresses and PIN codes.
- The platform relies on verbatim landmark descriptions recorded by ASHA workers (e.g., "Near Old Mango Tree, Dumbriguda").
- While culturally essential, automated geospatial geocoding for such landmarks cannot resolve to standard commercial map providers without local GPS coordinates.
